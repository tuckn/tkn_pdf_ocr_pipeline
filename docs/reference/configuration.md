# Configuration reference

Application ID: `pdf_ocr_pipeline`. CLI: `tkn-pdf-ocr`.
The packaged [example](../../src/pdf_ocr_pipeline/resources/config.example.yaml) is the
source of built-in defaults and the file generated by `config init`.

## Loading settings

Settings merge in this order, from lowest to highest priority:

1. Built-in defaults.
2. `~/.tkn/pdf_ocr_pipeline/config.yaml`.
3. `./.tkn/config.yaml` in the runtime working directory.
4. The file passed with `--config`.
5. Individual CLI options.

Nested `azure` and `sources.<source-id>` keys merge individually. New source IDs receive
per-source defaults before overlays. An empty `sources: {}` does not erase lower-layer
sources; use `enabled: false` to disable an inherited source. Relative paths are resolved against the
runtime working directory, for every layer; `~` means the user's home.
The source checkout and installed package location do not affect this rule.

Missing automatic files are skipped. An explicit missing file fails.
Each source is validated **before merging**, including its keys, types, version,
enums, and ranges. A higher-priority value cannot hide an invalid lower source.
Unknown keys and incorrect types fail. Configuration reads never migrate/write a file.

Every file declares `schema_version: "3.0.0"`; 3.0.x patches are accepted.
Missing versions, prereleases and other major/minor versions are rejected.
`config show` reports source versions, effective settings and the winning source for each
leaf value. Configuration reads do not rewrite files or read key/token values.

`config init [PATH]` creates the example, returns `unchanged` for identical bytes,
and refuses edited content. `--force` backs up the existing file before replacing it.
`--dry-run` previews without creating folders or files.

## Folder and PDF options

| Key | Default | Meaning / values |
| --- | --- | --- |
| `state_dir` | `~/.tkn/pdf_ocr_pipeline/state` | Durable jobs, run reports, and locks; share between scheduled/manual runs. |
| `min_age_seconds` | `30` | Nonnegative age threshold for **each file**, including `convert`. Newer files are skipped. |
| `max_pages` | `2000` | Integer 1..2000; pre-upload file page ceiling. |
| `max_file_mb` | `500` | Integer 1..500, interpreted as MiB (1,048,576 bytes); source and prepared-upload ceiling. |

Input, output and state roots in folder runs must be separate and non-nested.
Named queue runs validate these relationships across **all enabled sources**, even when
`--source` selects only one. Enumeration/setup errors stop before processing any file.
Single conversion allows two distinct files in the same folder.
Null is allowed only for optional strings in the example; empty strings are rejected.
No option silently interprets an empty value as another path or profile.

## Named queues (`sources`)

`sources` defaults to `{}`. After all configuration layers merge, an empty mapping
(including an omitted `sources`) resolves to one implicit source named `default`:

- `input_dir`: `~/.tkn/pdf_ocr_pipeline/data/incoming`
- `output_dir`: `~/.tkn/pdf_ocr_pipeline/data/searchable`
- `enabled: true`, `recursive: false`, `after_success: keep`, `output_suffix: ""`

`config show` exposes the resolved paths and marks their winning source as `built-in`.
The fallback is added only after merging, never alongside user-defined sources. Explicit
sources with missing paths still fail at run time; disabled sources do not trigger fallback.
An empty overlay does not clear lower-layer sources. Create the input directory before
running; output directories are created when a PDF is saved. Config reads and dry-run
remain read-only. `run --source default` selects the implicit queue.
A single folder pair is configured as one source, using the same model as multiple queues.
Each key is a stable source ID: 1–64 lowercase ASCII letters, digits, `_` or `-`, starting
with a letter/digit. Windows device names are rejected. IDs namespace job and delivery
records; renaming one loses deduplication against the previous ID.

| Key under `sources.<id>` | Default | Meaning |
| --- | --- | --- |
| `enabled` | `true` | Whether `run` includes this source. Disabled sources need not have folders yet. |
| `recursive` | `false` | Include subfolders for this source; preserve relative paths in its output. |
| `input_dir` | `null` | Required for each enabled source at run time. |
| `output_dir` | `null` | Required for each enabled source at run time. |
| `after_success` | `keep` | `keep` or `delete`; deletion only after saved-output verification and durable recording. |
| `output_suffix` | `""` | Literal filename suffix before `.pdf`; `_ocr` produces `name_ocr.pdf`. Path separators, control characters and invalid Windows filename characters are rejected. |

Top-level Azure options, `min_age_seconds`, limits and `state_dir` are shared.
`recursive` belongs only under each source; top-level `recursive` and CLI
`--recursive` / `--no-recursive` are not accepted.
Paths still resolve against the working directory; recursive runs preserve relative folders.
`run --source ID` selects one enabled source; unknown or disabled IDs are errors. All
sources disabled is a successful empty run. Individual file failures do not stop other files.
Top-level `input_dir` / `output_dir` and CLI `--input-dir` / `--output-dir` are not accepted.
`convert INPUT --output OUTPUT` requires an explicit output file, is independent of named
queues, and always keeps input.

```yaml
schema_version: "3.0.0"
sources:
  receipts:
    recursive: false
    input_dir: C:/path/to/receipts/1_rawPDF
    output_dir: C:/path/to/receipts/2_ocrPDF
    after_success: delete
    output_suffix: "_ocr"
  business-cards:
    recursive: true
    enabled: false
    input_dir: C:/path/to/cards/1_rawPDF
    output_dir: C:/path/to/cards/2_ocrPDF
    after_success: keep
    output_suffix: "_ocr"
azure:
  endpoint: https://<resource-name>.cognitiveservices.azure.com
```

`config show` includes the resolved source mapping and winning source for each leaf value.
Cross-source folder validation and required enabled paths are checked by `run --dry-run`.
Deletion is not a recycle-bin operation. Successful local storage does not confirm OneDrive
cloud synchronization. Named queues can copy already-searchable PDFs without Azure; they
hold unsupported/unsearchable results for review. See [delivery recovery](processing.md#named-queue-delivery).

## Azure options

All keys below belong under `azure:`.

| Key | Default | Meaning / values |
| --- | --- | --- |
| `endpoint` | `null` | Required for eligible OCR. HTTPS origin without credentials, query or path. |
| `auth_mode` | `browser` | `browser`, `default_credential`, or `key`. |
| `tenant_id` | `null` | Optional tenant ID/domain for browser login; unset uses the SDK organizations default. |
| `key_env` | `AZURE_DOCUMENT_INTELLIGENCE_KEY` | Environment variable **name**, never the key itself. |
| `api_version` | `"2024-11-30"` | The supported searchable-PDF API contract. |
| `locale` | `null` | Automatic language detection; optional hint such as `ja`. |
| `request_timeout_seconds` | `60` | Integer 1..86400; HTTP request timeout. Browser sign-in has a separate fixed 300-second timeout. |
| `poll_interval_seconds` | `2` | Integer 1..86400; delay between incomplete-result checks. |
| `poll_timeout_seconds` | `600` | Integer 1..86400; deadline for polling and download in one invocation. |
| `max_get_retries` | `3` | Integer 0..10; extra attempts per poll/download GET. POST is never retried automatically. |

`browser` uses [InteractiveBrowserCredential](https://learn.microsoft.com/en-us/python/api/azure-identity/azure.identity.interactivebrowsercredential?view=azure-python).
The first sign-in or a required reauthentication opens the system browser. Token refresh
and subsequent processes reuse an OS-encrypted cache isolated by application, endpoint,
and tenant. Unencrypted fallback is disabled. Account identifiers, without tokens, are
saved atomically below `~/.tkn/pdf_ocr_pipeline/authentication/`. Do not share these records;
they include account information. The Azure SDK owns the encrypted token-cache location.

`tkn-pdf-ocr auth login` obtains a token without uploading PDFs or invoking OCR. It does
not verify resource-level permissions. `--reauthenticate` prompts for account selection
even when the cached token works. `--dry-run` never initializes a credential, reads or
writes its cache, opens a browser, or makes a network request. Normal OCR prompts for
sign-in automatically when needed, before recording a billable submission intent.
`config show`, skipped documents and unchanged completed jobs do not authenticate.

Browser sign-in requires the browser and a local loopback callback. Its fixed timeout
is 300 seconds. The SDK development application's client ID is used, as in the similar
local CLIs. A dedicated production app registration is not provisioned by this CLI.
Browser cache reuse is not a guarantee of indefinitely unattended access; account/MFA
policy can require interaction again.

`default_credential` uses DefaultAzureCredential with Azure CLI, Azure Developer CLI,
Azure PowerShell, shared developer caches, VS Code, browser and broker credentials
explicitly excluded. Only configured environment, workload or managed identities are
eligible. This prevents a fallback to any external login command. Supply identity
settings outside this application; do not put secrets in YAML. The browser `tenant_id`
setting does not configure this identity chain.

For SDK cache details, see [TokenCachePersistenceOptions](https://learn.microsoft.com/en-us/python/api/azure-identity/azure.identity.tokencachepersistenceoptions?view=azure-python).

`key` reads the configured environment variable only for OCR execution or local
credential-presence validation during dry-run. It neither persists nor displays the key.
If the resource disables local authentication, use an Entra mode.
For public Azure Entra authentication, the token scope is
`https://cognitiveservices.azure.com/.default`.
Sovereign-cloud scopes are not implemented.

`--endpoint`, `--auth-mode` and `--locale` override their corresponding Azure keys.
The model is fixed to `prebuilt-read`; it is not a deployment name.

## Reprocessing consequences

Source SHA-256, canonical input/output paths and the processing fingerprint identify an OCR job.
Named sources additionally partition jobs by source ID. A separate handoff identity uses
source ID, canonical input path and input SHA-256; it excludes output path, suffix and OCR
settings. Completed handoffs prevent automatic republication after a downstream move.
Use `convert` with an explicit destination for a deliberate new conversion of a retained PDF.
The fingerprint includes PDF-processing revision, model, endpoint, API version, locale,
the explicit `--redo-ocr` flag. Changing these may create a different job.
Conflicting existing output still requires `--overwrite`.
Changing timeouts/authentication credentials does not force another OCR request.
The 0.3.0 image-preserving update uses a new processing revision. Earlier rasterized
outputs are not reused as completed results; their files and state remain intact.

Moving/deleting state removes knowledge needed for deduplication and resumption.
An existing PDF without matching state is protected as a conflict; it is not silently
trusted or replaced. Back up state alongside outputs if recovery matters.
